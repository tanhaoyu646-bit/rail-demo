# 2026-09-01 随机练习、阶段交互与资源回收

## 本轮范围

不更换几何、不改变已调整的右手抓握姿势、不上传或发布站点。原GLB保持只读。修改前相关源码备份在 `working/session-flow-before/`。

## 实现

- 正确携带项保持原有三证两规集合，只打乱11个选项的位置；点击、返回、重绘不会重新洗牌。
- 普通入口每轮产生新编号；固定 `seed` 或 `student` 可重放，不采集真实学生信息。刷新开始新一轮并清空流程，未实现账号或持久化成绩。
- 两条揭示分别变化命令号、教学线路、站名、行别、起止时间、两种参考施工事项的顺序；不是实时行车命令。保留两条数量以保证纸张近景可读。
- 默认70%一致、15%公布揭示差异、15%卡内差异；差异从命令号、开始时间、行别、进出站信号机内容中选一项。1000个固定种子中实际分布718/142/140，产生516种正文组合及1000种选项排列。
- 公布差异：报告→退出设备→靠近调度员按E→复核差异→回原设备重新划线核对。更正后的公布记录为独立副本，清除旧确认。
- 卡内差异仅首次写入注入，报告后可请调度员复核或返回重新写卡；再次验卡必须重新划线。不会循环注入错误。
- 整体顺序为一体机→副司机小组会→调度员人人核对→人车核对。错误阶段的人员只交谈/随机提示；已经完成的小组会不自动再次打开手帐。实际距离和遮挡检查保留。
- LKJ原型改用同轮数据与条数；仍未接入真实车辆或完整HXD3C驾驶台。

## 内存诊断与修复

发现旧手持物品仅从场景移除，未释放独占GPU资源；过期异步加载、翻开手帐和插卡取回亦有遗漏。增加统一独占资源释放（几何、材质、纹理、ImageBitmap），共用手模显式保留，不误释放其他实例；不再为即将加载的真手模预生成一套随后丢弃的备用手。

同一调试场景浏览器实测：

| 状态 | GPU几何 | GPU纹理 |
|---|---:|---:|
| 修复前，初始持纸 | 190 | 24 |
| 修复前，录音笔→手帐→录音笔 | 196 | 34 |
| 修复前，再收起，仍未回收 | 196 | 34 |
| 修复后，交替取放六次，手帐在手 | 190 | 27 |
| 修复后，再收起 | 188 | 23 |

上述对照在额外移除手部无效金属贴图之前完成。手材质金属度固定为0，粗糙度固定为0.78；其打包金属/粗糙度贴图没有视觉贡献，现从运行时移除并释放，保留原GLB、颜色和法线。按RGBA8+完整mipmap预算，少一张2048²贴图约节约21.3 MiB GPU存储；这是估算，不是操作系统进程内存实测。

最终版本再做录音笔→手帐→录音笔对照，录音笔在手为190个几何/25张纹理，收起后188个几何/22张纹理；纹理比上一轮再少1张，画面手模与物品仍正常。

`tools/audit-runtime-assets.mjs` 读取GLB内图像头和三角数：手模60,000面、三张2048²贴图、9.57 MiB下载；调度员179,998面、三张1024²贴图、7.50 MiB；每个扫描物品约60,000面、三张1024²贴图。下载文件大小不等于解码、GPU占用；JS堆受GC和浏览器上下文影响，本次不宣称总内存降低某一百分比。

页面隐藏时停止本轮渲染更新；已有DPR≤1.6、关闭阴影保留。诊断面板仅 `?diagnostics=1` 可见，正常课堂界面没有开发性提示。

## 部署答疑（未执行部署）

当前前端可静态托管。现有公共资源总计约61.3 MB，低于GitHub Pages发布站点1 GB限制，但手机还需控制器/贴图/模型预算适配。普通GitHub Pages网站通常公开，私有源码仓库不会自动保护网站；私有Pages的组织访问控制需要GitHub Enterprise Cloud。下载到浏览器的JS/GLB不能靠私有仓库或压缩加密隐身。

若实际部署到 `账号.github.io/仓库名/`，构建时还需配置该子路径的Vite base并验证模型资源URL；当前本地根路径服务不能不经配置就视为Pages发布验收。暂未上传，也未修改外网/防火墙访问权限。

仅师生访问宜用学校服务器或带服务端身份验证的部署；正式评分、班级成绩和账号另需后端。未上传教材图片、模型或学生数据。
